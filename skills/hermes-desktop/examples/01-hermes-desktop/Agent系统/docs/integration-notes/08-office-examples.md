# 办公/表格治理模型 — 示例印证（from examples/01-hermes-desktop，已实测）

> 本文件从 `references/02-integration-core.md#office` 抽出：该治理模型如何在该旗舰示例的「用户文件」这一更高危资产上落地。
> 属示例耦合内容，不进入技能核心骨干（通用治理模型见 `references/02-integration-core.md#office` §1–§7）。

---

本技能旗舰示例虽不操作表格，但**同一套治理模型已被用在"用户文件"这一更高危资产上**，
证明该模型可泛化到"任何用户资产改写"：

## 8.1 只读 + 路径白名单 + 沙箱预览（`file_preview.py`）

生成文件/图片要渲染给用户看，但**绝不能让前端直接读任意路径**（目录穿越风险）。
示例的 `file_preview.py` 贯彻：

- `resolve_safe()`：读取强制落在区间根目录内（`HERMES_HOME` / 工作目录 / 临时目录 / 用户主目录），
  拒绝 `..` 与软链越界；越界/不存在一律拒。
- 按扩展名 + 文件头魔数嗅探（手写魔数，规避 3.13 已移除的 `imghdr`，且排除可含脚本的 SVG）。
- 渲染用 **`<iframe sandbox>`（禁用脚本）/ `<img>`/`<pre>`**——即使内容里夹带脚本也跑不起来。

→ 对应治理模型的 **Layer 1 只读 + 预览**，且预览本身在沙箱里。

## 8.2 "生成文件内联预览"复用审批/确认闭环

`action_result` 检测到工具返回的是文件路径时，前端挂「📄 预览文件」按钮；点击才在
沙箱里渲染。这与 §5 的"提议 → 用户确认 → 落盘"是**同一控制流**：Agent 产出"指针"，
用户确认后才触及资产。

## 8.3 泛化结论

把 §2–§4 的 `EditOp` 换成你的资产操作类型（单元格 / 文档段落 / 数据库行 / 文件写），
`propose/commit/undo` + 白名单校验 + 事务 + 预览的四件套结构**完全不变**。
示例的 `file_preview` + 沙箱渲染就是"文件资产"这一具体类型的最小可用实现，可直接套用。
